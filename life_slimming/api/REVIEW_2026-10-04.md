# Portal source and API review — 2026-10-04

Read-only ERP inspection covered 189 API Server Script records and 121 Web Page
records. The portal maps 42 routes to 37 distinct page sources. Their recorded
modification times match the live pages (the local `hrms-dashboard---copy` source
corresponds to the live `hrms-dashboard-copy` document). This timestamp check
does not replace visual or business-flow validation.

## API updates

Of the original 141 catalog entries, 133 source hashes already matched ERP.
Eight differed and were refreshed using the existing native migration adapters:

- `life_approval_report_conversion_action`
- `cc_get_leads`
- `cc_walkin_update`

The local appointment fields and enrichment in `cc_get_leads` remain in place,
including the new query-search response. Four previously missing page dependencies
were added with authenticated POST endpoints and catalog/client mappings:

- `cc_phone_lookup` — call-centre dashboard
- `life_stock_receipt_employee_search` — stock receipts
- `life_client_record_book_api` — enrollment register
- `life_client360_branch_patient_lookup` — client information

The catalog now contains 145 APIs. Unrelated live test APIs were not imported.
ERP also contains a second enabled script named `CC update lead Testing kavya`
with API method `cc_update_lead`. The existing local mapping to the original
`cc_update_lead` module is retained; the duplicate is not substituted.

## UI and loading fixes

- Embedded-page readiness uses DOMContentLoaded rather than waiting for every
  image or external widget to finish. Pending API requests still hold the loader.
- Duplicate legacy branding/navigation receives an inline important hiding rule,
  because Approvals CSS overrode the shared stylesheet in a browser test.
  Existing DOM hooks remain available to page scripts.
- The access-control unit fixture now supplies the imported menu data correctly.

## Validation and limits

- All 72 embedded JavaScript blocks compile.
- All 12 added/refreshed API bodies match live source syntax trees, allowing the
  established adapters and the documented local appointment integration.
- JavaScript suites, portal Python tests, appointment/ConVox Python tests, and
  the production portal build pass.
- Audit and HR browser fixtures cover desktop/mobile layouts, errors and retry.
- All 41 embedded routes pass the workspace browser fixture: one shared header,
  hidden duplicate branding, concurrent-request loading and denied-route checks.
  The remaining mapped control route uses the native access-control page.

API source parity does not prove financial, stock or clinical business results.
No live transactions were executed and no remote Server Script or Web Page was
edited. Browser checks use isolated fixture data. Production deployment, worker
reload and cache clearing are not part of this review. The billing bundle still
triggers Vite's size warning and merits separate performance profiling.
